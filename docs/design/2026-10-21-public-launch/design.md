# Paper Craft Print 1.0.0 공개 출시 설계

사용자가 2026-10-21 전달한 계획을 구현하라고 명시했다. 이 문서는 그 승인 범위를 실행 가능한 형태로 기록한다. 대상은 Seolee Apps, `com.seoleeapps.papercraftprint`, Google Play 무료 앱 1.0.0, 배포 가능한 전 세계 국가 100% 공개다. 계정 확인 잠금 해제 전 앱 생성과 업로드를 진행하지 않는다.

## 흐름과 화면

```text
홈: 6종 전개도 미리보기 → 도안 선택 → 앞면과 뒷면 사진, 문구, 치수 편집
내 작업: 저장된 초안 → 열기, 복제, 삭제
편집 → A4 또는 Letter 출력 배치 → PDF 생성 → 저장, 공유, 인쇄
설정: 한국어와 영어, 광고 개인정보 선택
홈과 내 작업 하단: 구분선과 여백으로 버튼에서 분리한 적응형 배너 1개
```

기존 색상과 구성요소를 유지한다. 홈의 실제 전개도 썸네일을 6종으로 확장한다. 새 도안은 선물 태그, 책갈피, 손잡이 없는 종이 쇼핑백이다. 태그와 책갈피는 두 면을 나란히 한 장에 인쇄하고 가운데를 접어 빈 뒷면을 붙인다. 접이식 카드는 겉면만 인쇄하고 안쪽은 비운다. 쇼핑백은 앞면, 옆면, 뒷면, 옆면을 잇고 옆 접착 탭과 겹치는 바닥 플랩을 붙인다. 조립 안내는 편집과 출력에 한국어와 영어로, PDF에는 짧은 영어로 표시한다.

## 구조와 데이터

`TemplateKind`, `TEMPLATES`를 확장해 사진, 문구, 치수, 전개도, 반복 배치와 PDF가 같은 도안 기하를 사용한다. 기존 kind와 SQLite 스키마를 유지한다. 예전 kind 없는 초안은 봉투로 정규화하고 보상 권한, 사진과 복제 동작을 보존한다. 등록부 외 별도 새 도안 분기를 만들지 않는다.

RN Web은 실제 `App.tsx`, `Preview.tsx`, PDF 엔진을 실행한다. 광고, 파일 선택, SQLite, 저장과 OS 공유 및 인쇄만 플랫폼 경계의 웹 구현으로 교체한다. 웹 개발 화면의 광고는 대역이며 Android SDK 통과 근거로 쓰지 않는다. 네이티브와 웹은 빌드 때 파일 확장자로 선택한다.

배너는 UMP 동의 조회 후 허용될 때만 SDK 초기화와 요청을 한다. 동의 변경 중에는 기존 광고를 내리고 재확인 후 새로 요청한다. 초기화는 중복 실행하지 않는다. 오류, 동의 불가와 재고 없음은 제작과 무료 PDF 출력을 막지 않는다. 자동 갱신은 SDK에 맡긴다. 편집, 출력, 완료와 설정에는 배너가 없다. 개발은 Google 테스트 ID, 운영은 해당 앱의 확인된 공개 ID를 사용한다.

## 인수조건과 검수

- 6종 기본값과 모든 프리셋은 A4와 Letter에 100% 치수로 들어간다. 범위 밖 및 종이 초과 치수는 출력 전 차단한다.
- 자르기 선의 닫힌 윤곽, 접는 선, 접착 영역과 조립 안내를 제공한다. 50 mm 벡터 확인선과 안내까지 종이 안전 여백 안에 둔다.
- 앞면과 뒷면 사진, 문구 방향, 반복 배치, PDF 렌더, 한국어와 영어를 검사한다.
- 저장, 재시작 복구, 예전 초안, 복제와 삭제, 보상 중복 방지, 광고 오류와 동의 변경을 검사한다.
- 실제 RN Web 핵심 여정으로 L3 전체 회귀, 독립 기능 및 UX 검수 3회를 한다. 매 회차 사전 계획과 실행 결과를 기록한다.
- 실제 Android 배너와 UMP, 파일 선택 및 OS 출력은 개발 검수 후 남은 필수 항목만 별도 기기 사용 승인받아 확인한다. 승인 전 조회도 하지 않는다.
- 실물 인쇄 및 조립은 사용자 결정에 따라 출시 조건에서 제외한다. 치수와 조립의 실물 품질은 미확인으로 명시한다.

순수 기하는 실패 테스트부터 추가한다. 화면과 공급자 설정은 실제 실행, 독립 검수와 readback으로 확인한다. 공개 전 전체 Git 이력과 추적 파일을 비밀값 및 배포 불필요 파일 검사한다. 공개 저장소의 기존 이력은 보존하고 기능은 Ready PR로 반영한다.

## 출시와 복구

서명된 AAB, 실제 화면, 한국어와 영어 소개, 개인정보처리방침, 광고와 Data safety 선언을 준비한다. 등록된 전용 업로드 키를 재사용한다. 없다면 승인 범위 안에서 생성하고 암호화 백업 및 임시 복원 확인을 통과한다. 중앙 검증기는 빌드, 업로드와 공개 전 각각 실행한다. 계정 확인, 기기 승인, 검증기 실패는 별도 gate로 남긴다. 업로드, 심사, 승인, 공개와 실제 스토어 readback을 구분한다. AdMob 승인 및 운영 송출도 별도로 기록한다.

원래 dirty checkout과 `.serena/`를 보존하고 `feat/public-launch` worktree에서 작업한다. 문제가 있으면 PR을 병합하지 않는다. 기존 사용자 초안이나 보상 데이터는 초기화하지 않는다. iOS, 앱인토스, 로그인, 서버, Firebase, 분석과 결제는 제외한다.
